Como usar IA sem atrapalhar o aprendizado

A IA é o melhor professor particular que já existiu, mas também pode virar uma cola que impede você de aprender. A diferença está em como você pergunta.

  1. Tente sozinho primeiro. Fique pelo menos 20 minutos travado antes de perguntar. O esforço de travar é onde o cérebro aprende.
  2. Peça dica, não resposta. Comece a pergunta com "não me dê o código, só uma dica".
  3. Dê contexto completo. Cole o erro inteiro, o código, o que você esperava que acontecesse e o que você já tentou.
  4. Nunca use código que você não consegue explicar. Se a IA gerou, leia linha por linha e explique cada uma em voz alta. Se não conseguir, pergunte até entender.
  5. Explique de volta. Depois de aprender algo, explique para a IA com suas palavras e peça para ela corrigir o que você errou.
  6. Peça para ser testado. "Me faça 5 perguntas sobre arrays" ou "me dê 3 exercícios parecidos com esse".
  7. Desconfie. A IA erra com confiança. Confira na documentação (MDN, react.dev) e rode o código para ver se funciona.

O papel da IA muda conforme você avança

fases 0 a 1ProfessorSó explica e dá dicas. Autocompletar de código (Copilot, Cursor) desligado.
fases 2 a 4RevisorVocê escreve tudo; a IA revisa, explica erros e sugere melhorias.
fases 5 a 7DuplaPode gerar partes repetitivas que você já sabe fazer. Autocompletar liberado.
fases 8 a 10EquipeAgentes como o Claude Code fazem tarefas inteiras; você planeja, revisa cada mudança e testa.

Prompt de professor (cole no início da conversa)

Você é meu professor de programação. Estou aprendendo JavaScript do zero.
Regras:
1. Nunca me dê a solução completa de um exercício.
2. Dê uma dica por vez, começando pela mais sutil. Só dê a próxima se eu pedir.
3. Quando eu mostrar código com erro, me faça uma pergunta que me leve a encontrar o erro antes de explicar.
4. Explique em português simples, com analogias do dia a dia.
5. No fim de cada explicação, me faça uma pergunta curta para ver se entendi.

Como ajudar sem atrapalhar

  • Peça para ele explicar o código em voz alta, linha por linha. Se não souber explicar, ainda não entendeu.
  • Travou mais de 30 minutos? Dê uma dica pequena, nunca a resposta inteira.
  • Depois que funcionar, desafie: "e se o número for negativo?", "e se a lista estiver vazia?", "e se a API cair?".
  • Uma vez por mês, abra o GitHub dele e faça um code review de verdade, com comentários na PR.
  • Não pule fases. Quem vai para React sem saber lógica e DOM trava logo em seguida.
O progresso fica salvo só neste navegador.
